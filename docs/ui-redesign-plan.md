## 1. 目标与边界

**目标**

1. 客户打开页面，3 秒内知道"这个房间现在好不好、系统建议做什么"，并且知道下一步点哪里。
2. 信息逐层展开，不把所有面板铺在首页。
3. 三维房间保持写实：Revit 模型里的族全部保留，并提升材质和光照质感。
4. 视觉轻盈通透，参考 Apple Liquid Glass；动效多，但每个动效都对应真实的数据变化或用户操作。
5. 体现数据的丰富程度，但不夸大、不伪造。

**边界**

- **内容不变**：现有页面上的所有信息和功能都保留，只重新组织位置、层级和样式。第 14 节有逐项对照表，实现时逐项核对。
- **保留**：三种语言（简体中文、繁體中文、English）、浅色和深色主题（默认浅色）、现有的数据桥接协议（WebSocket，端口 8787，只新增消息，不改现有消息）、Fragments 模型加载方式。
- **不引入前端框架**：继续用原生 JS + Vite + three.js。动效用 CSS、Web Animations API 和 View Transitions API 实现，必要时可以加一个轻量动画库（如 Motion 的原生 JS 版本），引入前先说明理由。

## 2. 设计原则

1. **场景是主角，界面是框架。** 三维房间占满整个画面；界面元素浮在场景上方，集中在画面边缘。
2. **三层逐步展开。** 第一层（首页）只回答"现在好不好"；第二层（主题）按客户关心的问题分类；第三层（详情）才展示单个传感器和完整图表。
3. **只有真实变化的东西才动。** 新读数到达时数字滚动、标记闪一下；数据过期的模块是静止、偏灰的。不做循环播放的装饰性动画（例外见第 12 节规则）。
4. **用深度体现数据量，而不是用格子数量。** 一条带历史、限值线和 AI 预测的 CO₂ 曲线，比八个只有一个数字的方块更有说服力。
5. **诚实。** 每个数字都能看出是多久以前的；没有数据的模块不显示，而不是显示"—"；模拟数据和回放数据永远带着明显标记。
6. **玻璃只用在导航和控制层。** 承载数据的面板用更厚、更不透明的磨砂；玻璃不叠玻璃。
7. **细节服务于主题。** 每个标志性效果都要表达"真实房间 ↔ 数字孪生"的关系（真实时间、BIM 数字层、真实历史数据），不做与主题无关的炫技。

## 4. 第一层：首页

### 4.1 布局（1440 × 900 为基准）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ZB202 · 实时 · 3 分钟前更新        [CO₂ 612] [26.1°] [58%] [3 人]    ● 一切正常 [简|繁|EN] [📷 ⚙] │
│ 室外 31° · 晴                      "空气良好，3 人在使用"                          │
│                                                                        │
│ ┌─────────────┐                                                        │
│ │ AI 新风推荐  │                 写实三维房间                            │
│ │ 98 L/s      │                 （占满整个画面）                         │
│ │ 风阀 34%     │                                                        │
│ │ 14:00 组会…  │                                                        │
│ └─────────────┘                                                        │
│                                                                        │
│                 [ 总览 · 环境 · 能耗 · 设备 · AI ]                        │
└──────────────────────────────────────────────────────────────────────┘
```

- **左上：身份区。** 房间名"ZB202"、实时状态（"实时 · 3 分钟前更新"，数据过期时变为"数据延迟 · 最后更新 14:02"）、室外温度和天气一行小字、香港时间。原有的标题"ZB202 AI-Empowered Digital Twin Platform"缩小为身份区的副标题。
- **顶部居中：状态胶囊 + 一句话状态。** 见 4.2、4.3。演示模式和回放时，这里的上方另有标记（第 11、13.5 节）。
- **右上：告警胶囊 + 语言切换 + 工具按钮组（截图、设置）。** 语言切换常驻显示，点一下即可切换（第 6.4 节）；截图和设置共用一块薄玻璃背景（参考 Apple 工具栏分组）。见第 6 节、第 13.10 节。
- **左侧：AI 推荐小卡。** 见第 7 节。
- **底部居中：标签栏。** 总览、环境、能耗、设备、AI 五项。玻璃材质，选中项有一个滑动的玻璃"滑块"。
- **右侧留空**，让场景透气；第二层的主题面板从右侧出现。

首页**最多 4 个数字胶囊 + 1 张 AI 卡**，不再出现其他数据卡片。

### 4.2 状态胶囊

- 四个胶囊：CO₂（ppm）、温度（°C）、湿度（%）、人数。
  - 数值取房间代表值：CO₂ 和温湿度取 5 个环境传感器（AM103-05/06/07/08、AM308-01）的平均值，与策略文档一致。
  - 人数：有实测数据时显示"人数"；只有估计值时显示"估计人数"；两者都没有时**不显示这个胶囊**。不显示置信度。
- 每个胶囊左侧有一个状态色点（良好 / 注意 / 超标）。CO₂ 阈值：< 800 良好，800–1000 注意，> 1000 超标（对应香港 IAQ 认证的卓越级和良好级）。温湿度和 PM2.5 的阈值见第 4.5 节。
- **悬停或获得焦点时展开**，显示过去 24 小时的迷你曲线和"x 分钟前"。这是体现数据深度的主要手段，而且全部是真实数据。
- **点击**：进入"环境"主题，并把该指标设为当前焦点（场景标记切换为显示该指标，详见 5.2）。
- 数字使用等宽数字（`font-variant-numeric: tabular-nums`），新读数到达时数字从旧值滚动到新值（600 ms），读数之间**不做插值动画**。
- 胶囊中的单位和数值带术语说明（第 13.9 节）。

### 4.3 房间状态（参考 Flighty 的按阶段显示）

根据人数和时间判断房间处于哪种状态，决定一句话状态的内容，以及 AI 卡片和场景强调什么：

| 状态 | 判断条件 | 一句话示例 | 强调 |
| --- | --- | --- | --- |
| 使用中 | 人数 ≥ 1（实测或估计） | "空气良好，3 人在使用" / "CO₂ 正在上升，建议加大新风" | CO₂、AI 新风推荐 |
| 空置 | 工作时间（周一至周五 9:00–19:00，可配置）且人数为 0 | "房间空置，6 个插座中 2 个仍在用电" | 能耗 |
| 非工作时间 | 工作时间以外 | "非工作时间，门已关闭，无漏水" | 门磁、漏水、告警 |
| 未知 | 没有任何人数来源 | 只按时间判断，不对人数下结论 | 只描述环境数据 |

一句话状态由规则生成，规则写成一个独立模块（`ui/room-state.js`），以便之后修改和测试。

### 4.4 数据时效显示

- 全局：身份区显示最近一次读数的时间。
- 每个数字：悬停时显示"x 分钟前"。
- 超过 15 分钟（沿用 `INFLUX_STALE_AFTER_MS`）没有新数据的指标：数字变灰，状态点变为灰色，不再有任何动画。
- 可选（需要桥接配合）：身份区加一行"23 个传感器 · 今日 1,2xx 条读数"。读数条数由桥接从 InfluxDB 统计后推送，是真实数字。

### 4.5 环境阈值（暂定，待同事确认）

所有阈值写在一个配置文件中（如 `web/src/twin/config/thresholds.json`），以后修改不需要改代码。

| 指标 | 良好 | 注意 | 超出 | 依据 |
| --- | --- | --- | --- | --- |
| CO₂ | < 800 ppm | 800–1000 ppm | > 1000 ppm | 香港室内空气质素认证计划：卓越级 800、良好级 1000（8 小时平均） |
| 温度 | 22–26 °C | 20–22 或 26–28 °C | < 20 °C 偏冷 / > 28 °C 偏热 | 常用办公室舒适范围；香港政府建议夏季室内温度 24–26 °C |
| 相对湿度 | 40–65% | 30–40% 或 65–70% | < 30% 偏干 / > 70% 偏湿 | ASHRAE 62.1 建议空调空间湿度不高于 65%；40–60% 为常用的健康范围 |
| PM2.5 | ≤ 25 µg/m³ | 25–35 µg/m³ | > 35 µg/m³ | 按香港室内空气质素认证计划（2019 修订）的 8 小时指标，**数值请同事核对** |

说明：

- 香港室内空气质素认证计划在 2019 年 7 月修订时，**删除了温度、相对湿度和风速**这三项，理由是它们属于舒适度而不直接关系空气质量。所以温湿度没有本地官方的"良好 / 卓越"标准，上表是通用的舒适范围。
- 温湿度的状态文字用"舒适 / 注意 / 偏冷 / 偏热 / 偏干 / 偏湿"，不用"超标"。
- 状态判断用房间代表值（第 4.2 节），单个传感器的光晕颜色用该传感器自己的读数。

## 5. 第二层：主题

### 5.1 通用交互

- 点击底部标签或首页胶囊进入主题：
  1. 镜头在 1000 ms 内飞到该主题的预设机位（缓动 ease-in-out）。
  2. 场景图层按主题切换（哪些构件可见、标记显示什么）。
  3. 右侧滑出主题面板（宽 380–420 px，上下各留 16 px 间距，不贴边），使用"厚玻璃"材质（第 8 节）。
- 首页的 AI 卡片和状态胶囊在进入主题后仍然保留，但状态胶囊收缩为只显示数字的紧凑样式。
- 用户手动转动视角后，标签栏上方出现一个"回到默认视角"按钮。
- 按 Esc 或再次点击"总览"返回首页。
- URL 同步当前状态（如 `twin.html#environment`、`twin.html#sensor=AM103-05`），刷新或分享链接后能回到同一位置。

### 5.2 环境

- **机位**：从门口方向斜向下看中间会议桌，能同时看到 5 个环境传感器和座位。
- **场景**：
  - 5 个环境传感器标记上方显示当前焦点指标的数值（默认 CO₂）。
  - 每个传感器下方的地面上有一圈柔和的光晕，颜色对应良好 / 注意 / 超标。这是唯一的"着色"方式，不改模型材质。
  - 有座位占用数据时，座位上方显示淡淡的占用标记。
- **面板内容**（从上到下）：
  1. 指标切换：CO₂ / 温度 / 湿度 / PM2.5 / 噪声。切换时场景标记同步切换。
  2. **CO₂ 时间轴**（参考 Windy）：左侧是实测历史，右侧是 AI 预测（有 `recommendation` 数据时），中间一条"现在"竖线，加一条 800 ppm 限值线。历史范围沿用 1h / 12h / 24h / 自定义小时数。没有预测数据时只显示历史。时间轴左侧有"回放"按钮（第 13.5 节）。
  3. 室内环境：温度、相对湿度、CO₂、PM2.5、噪声、人数（来自原"Indoor Environment"卡片）。
  4. 室外环境：干球温度、相对湿度、风速风向、太阳辐射（来自原"Outdoor Environment"卡片，香港天文台京士柏站）。太阳辐射超过 30 分钟视为缺失，沿用现有逻辑。
  5. 温度、湿度趋势图（当前焦点指标以外的两个）。
- 某项指标没有任何数据源时（比如目前的 PM2.5、噪声如果没有数据），**整行隐藏**，不显示"—"。

### 5.3 能耗

- **机位**：能看到墙上插座的位置。
- **场景（参考 Tesla 能量流）**：
  - 每个正在用电的插座（WS523）发出一条细光线，沿墙面流向一个"总用电"节点（建议放在门边）。
  - 光线流动速度与该插座的有功功率成正比；功率为 0 时没有光线；插座关闭时标记变暗。
  - 光线只在收到真实功率数据时出现，数据过期时停止流动。
  - **流线只在能耗主题中显示**。插座几乎总有设备在用电，如果流线在所有页面都显示，场景就永远需要连续渲染，按需渲染会失效（见第 13.1 节）。
  - 注意：IFC 里只有 WS523-02、03、04 有位置，WS523-01、05、06 没有。需要在 Revit 里补放这三个插座并重新导出；补之前，这三个插座只在面板里显示，场景中不画光线。
- **面板内容**（来自原"Socket Control"卡片，内容不变）：
  1. 总用电功率（kW），大号数字。
  2. 6 个插座开关，每行显示名称、当前功率、开关状态。总开关"All"保留。
  3. **控制需要确认**：这些开关会通过 MQTT 真实控制设备。点击开关后，开关先进入"等待确认"状态，弹出一个从开关处长出来的小确认框（"关闭 WS523-03？"），确认后才发送。之后依次显示"已排队 → 已发送 → 已生效"（对应现有的 `control-queued`、`control-result` 和遥测回读），失败时显示原因。
  4. 用电曲线：今日 / 7 天 / 30 天。
- 控制不可用（MQTT 未连接）时，开关显示为只读，并用一行小字说明原因。

### 5.4 设备

- **机位**：较高的俯视角度，显示 MEP（风管、风口），墙体自动淡出以便看到室内（见 9.3）。
- **场景**：显示全部传感器标记和 MEP 构件。悬停可选构件时显示淡描边（第 13.8 节）。
- **面板内容**（来自原 IoT 传感器列表和 overview.html，内容不变）：
  1. 状态汇总：在线 / 离线 / 故障数量，电池 ≥ 50% / 20–49% / < 20% 数量（来自原告警卡片的两个环形图，改为横向的小条形分布，更省空间）。
  2. 搜索框。
  3. 分类：全部 / MEP；传感器类别标签（环境、占用、门磁、漏水、插座）。
  4. 列表 / 表格切换（来自 overview.html 的"卡片 / 表格"）。表格列：设备名、编号、状态、最新数据。
  5. 模型图层开关（Architecture / MEP / 传感器显示模式），放在面板底部的"图层"折叠区。
- 列表中选中某个设备时，镜头飞到该设备，并打开第三层的传感器详情。
- AHU 运行数据接入后，在这里增加"AHU"分组（送回风温度、水阀、新风阀、风机频率、温度设定），接入前不显示。

## 6. 告警、截图与设置

### 6.1 告警（不再占用一个标签）

- 右上角一个告警胶囊：
  - 无告警时：一个小绿点 + "一切正常"。
  - 有告警时：胶囊展开，变为橙色或红色，显示数量（如"2 项告警"）。
- **新告警到达时**：从顶部弹出一条横幅（类似 iPhone 的实时活动），停留 6 秒后收回到告警胶囊；同时场景中对应传感器的标记脉动一次。
- 点击告警胶囊：从胶囊位置长出一个弹出面板，内容来自原"Alarm"卡片：
  - 传感器状态和电池状态分布
  - 告警列表，筛选：进行中 / 已确认 / 全部
  - 点击某条告警，镜头飞到对应设备并打开详情。

### 6.2 截图

### 6.3 设置

### 6.4 语言切换（常驻右上角）

- 切换时：
  - 文字做 150 ms 的交叉淡入淡出，不整页闪烁；胶囊和按钮宽度随文字长度平滑变化。

- 英文文案通常比中文长 1.5 倍左右。所有胶囊、按钮、面板标题都要用英文检查一遍，不允许截断或换行错位。

## 8. 视觉规范

### 8.1 玻璃材质（两种厚度）

| 材质 | 用途 | 浅色模式 | 深色模式 |
| --- | --- | --- | --- |
| 薄玻璃 | 标签栏、状态胶囊、告警胶囊、工具按钮组、身份区 | 背景 `rgba(255,255,255,0.42)`，`backdrop-filter: blur(20px) saturate(1.8)` | 背景 `rgba(28,30,34,0.45)`，同样的模糊 |
| 厚玻璃 | 主题面板、传感器详情、AI 小卡、弹出面板 | 背景 `rgba(250,251,253,0.80)`，`blur(36px) saturate(1.6)` | 背景 `rgba(22,24,28,0.80)` |
| 全屏 | AI 详情页展开后 | 背景不透明度 0.94 | 背景不透明度 0.94 |

共同细节：

- 上边缘 1 px 内高光：`box-shadow: inset 0 1px 0 rgba(255,255,255,0.6)`（深色模式 0.12），再加一层柔和外阴影 `0 8px 32px rgba(15,23,42,0.12)`。
- 鼠标在玻璃上移动时有跟随的反光（第 13.12 节）。
- **不要尝试做折射效果**（SVG 位移滤镜只在部分浏览器生效，而且在 WebGL 画布上性能很差）。用模糊、饱和度和边缘高光来表现玻璃感。
- **同一位置最多一层玻璃**，玻璃上不再放玻璃；全屏同时可见的玻璃元素不超过 3 组（标签栏、胶囊组、一个面板）。
- `@media (prefers-reduced-transparency: reduce)` 或设置中选择"降低透明度"时：所有玻璃改为不透明背景（浅色 `#F6F7F9`，深色 `#16181C`），去掉模糊。
- 所有承载数字的文字与实际背景的对比度不低于 4.5:1。由于背景是三维场景，并且会随时间和天气变化（第 13.2 节），需要在最亮（晴天正午）和最暗（夜间）的状态下分别检查。

### 8.2 圆角、间距、字体

- 圆角同心：最外层面板 28 px；面板内部元素圆角 = 28 − 内边距（例如内边距 12 px 时为 16 px）；胶囊和标签栏用全圆角。
- 间距基准 4 px，常用 8 / 12 / 16 / 24 / 32。
- 字号：大数字 32–40 px（面板中的主值），胶囊数字 17 px，正文 14 px，说明文字 12 px（不小于 12 px）。

### 8.2.1 字体

**现状的问题**

- twin.html 从 Google Fonts 加载 Noto Sans SC（思源黑体简体），overview.html 还向 Google Fonts 请求"SF Pro Display"。Google Fonts 上没有 SF Pro，这个请求是无效的；而且 SF Pro 的许可只允许用于苹果平台的界面设计稿，不能打包放进网页。
- 繁体中文界面也在用简体字形的 Noto Sans SC。简体版和繁体版思源黑体的部分字形写法不同，繁体界面应该用繁体版字体。
- 字体依赖 Google Fonts 在线加载。如果以后的服务器或客户网络访问 Google 不稳定，字体会加载失败或很慢。
- 方案 v0.1 写的"优先使用系统字体"会导致苹果电脑和 Windows 上看起来不一样（苹方 vs 微软雅黑），实验室大屏多半由 Windows 电脑驱动，展示效果不可控。

**采用的方案：自托管 Inter + 鸿蒙字体（HarmonyOS Sans）**

| 用途 | 字体 | 理由 |
| --- | --- | --- |
| 英文、数字、单位 | **Inter**（可变字重，SIL 开源许可） | 比例和气质最接近苹果的 SF Pro；支持等宽数字（`tnum`），数字更新时不会左右跳动；字重可以细到 300，适合"轻盈"的大号数字 |
| 简体中文 | **HarmonyOS Sans SC** | 现代、干净，有"科技感"，接近手机系统界面的观感；华为免费开放，可商用 |
| 繁体中文 | **HarmonyOS Sans TC** | 繁体字形，与简体版风格一致 |
| 代码类信息（GlobalId、设备编号） | 保留现有的 `ui-monospace` 系统等宽字体 | 只在内部模式和 BIM 属性中出现，不需要额外加载 |

字体栈写法（英文字体放在前面，数字和字母用 Inter，汉字自动落到思源黑体）：

```css
:root:lang(zh-Hans) { --font-ui: "Inter", "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif; }
:root:lang(zh-Hant) { --font-ui: "Inter", "HarmonyOS Sans TC", "PingFang HK", "Microsoft JhengHei", sans-serif; }
:root:lang(en)      { --font-ui: "Inter", "HarmonyOS Sans SC", system-ui, sans-serif; }
```

**加载方式**

- 所有字体文件放在项目中自托管（`web/public/fonts/`），不再依赖 Google Fonts。
- 中文字体完整文件每个字重有几 MB，必须**分片**：按 Unicode 范围切成很多小文件（与 Google Fonts 的做法相同），页面只下载实际用到的那几片。可以用 cn-font-split 这类工具在构建时生成。界面文案中的汉字有限，首屏通常只需要下载几百 KB。
- 字重只用 300（大号数字）、400（正文）、500（标签和标题）、700（少量强调），不加载其他字重。鸿蒙字体提供 Thin / Light / Regular / Medium / Bold / Black 六种字重，没有 600，所以标题统一用 500。
- 鸿蒙字体从华为官方渠道下载（简体版和繁体版分别下载），**使用前阅读其许可协议全文**，确认允许网页内嵌（自托管并分片）的用法；如有限制，回退为思源黑体（Noto Sans SC / Noto Sans HK），字体栈其余部分不变。
- `font-display: swap`；首屏关键字体（Inter）用 `<link rel="preload">` 预加载。
- 字体还没加载完时，字体栈中的系统字体（苹方 / 微软雅黑）作为回退，页面不会空白。

**排版细节**

- 大号数字：Inter 300，字距略收紧（`letter-spacing: -0.02em`），这是"轻盈"感的主要来源。
- 所有数字开启等宽数字：`font-variant-numeric: tabular-nums`。
- 中文正文行高 1.6，英文 1.45；中英文混排时不手动加空格。
- 单位（ppm、°C、L/s）比数值小两级、颜色更浅，例如"612 ppm"中 ppm 为 13 px、次要色。

**备选方案：思源黑体**

如果鸿蒙字体的许可不允许网页内嵌，改用思源黑体（Noto Sans SC 用于简体、Noto Sans HK 用于繁体，SIL 开源许可）。

### 8.3 颜色

- 中性色为主，一个强调色（系统蓝 `#0A84FF` 一类），用于选中状态、描边和交互元素。
- 状态色：良好绿、注意橙、超标红、离线灰。**绿和红之间同时拉开明度差**，并且每个状态点旁边都有文字或图标，不只靠颜色区分。
- 模式标记色：演示模式用橙色，回放用靛蓝色，两者明显区分。
- 所有颜色定义为 CSS 变量，放在 `styles/tokens.css`，浅色和深色各一套。替换现有 `theme.css` 中分散的颜色。

### 8.4 图标

继续使用 Phosphor Icons（已有依赖）。

### 8.5 自适应布局与触控（大屏触摸屏 + 笔记本）

主要展示设备是**实验室大屏（触摸屏）**，也会在**笔记本**上展示。同一个页面自适应，不做两套页面。

**按视口宽度（CSS 像素）分三档**

注意 Windows 的显示缩放会改变 CSS 像素宽度（例如 4K 屏在 150% 缩放下为 2560 px），所以按 CSS 像素判断，不按物理分辨率。

| 档位 | 条件 | 布局 |
| --- | --- | --- |
| 标准 | 1280–1919 px（笔记本） | 本方案的基准布局 |
| 大屏 | ≥ 1920 px，或 URL 参数 `?kiosk=1` | 整体界面按比例放大约 1.25–1.5 倍（根字号用 `clamp()` 随视口宽度变化）；面板加宽；状态胶囊和一句话状态更大，适合远距离观看；触控目标 ≥ 56 px |
| 窄屏 | < 1280 px（平板、缩小的浏览器窗口） | 主题面板和传感器详情改为从底部升起的半屏面板，可上拉到全屏；AI 小卡收起为一个按钮；状态胶囊可横向滑动 |

手机竖屏保留现有的横屏提示，不作为本次重点。

**触控规则（`(pointer: coarse)` 或 `(hover: none)` 时启用）**

- **所有悬停功能都有点击替代**，不能有只能悬停才看得到的信息：
  - 状态胶囊：点击直接进入环境主题（24 小时曲线在环境主题中可以看到，不依赖悬停展开）。
  - 术语说明：点击带虚线的词弹出说明，点击别处关闭。
  - 图表：手指按住并左右拖动查看具体时间和数值。
  - 标记读数预览：点击标记即选中并打开详情。
- 触控目标最小 48 px（大屏 56 px）；标记磁吸半径 44 px。
- 三维场景手势：单指旋转，双指缩放和平移；长按为透视镜（第 13.4 节）。画布设置 `touch-action: none`；禁止浏览器的双击放大、长按菜单、下拉刷新和页面回弹；界面上的文字不可被选中（数据表格除外）。
- 玻璃跟随反光在触屏上关闭，改为手指按下时在触点处出现一次性的柔和高光。
- 大屏通常没有键盘：每一层（主题面板、详情、AI 详情页、弹出面板）都必须有可见的关闭或返回按钮，不能只依赖 Esc。
- 大屏使用 `?kiosk=1` 打开，自动启用待机展示（第 13.7 节）和"中"档画质起步（第 13.13 节）。

## 9. 三维场景：写实渲染

**原则：保留 Revit 模型的全部族和细节，通过材质和光照提升质感，不做简化。**

### 9.1 现状

- 现有 IFC 中，建筑模型有材质名称（玻璃 `.Vidro`、铝、`Plank-HPL-white`、`Plank-HPL-black`、镀铬 `Cromado`、镀锌钢、石膏、混凝土、`TV - Glass` 等）和基础颜色，但没有贴图；MEP 模型没有材质。因此网页显示偏"假"。
- 现有 IFC 中家具有 4 件（桌子、电视、展示柜、置物架）。**已确认导出时没有丢失族**，Revit 模型中就是这些构件。
- IFC 中的场地坐标是 Revit 默认值（约 51.5°N，伦敦），没有设置真北方向。**已确认：房间大门朝南。** 大门位于 IFC 坐标 y ≈ −4.0 m 的墙上，因此 **IFC 的 +Y 方向即为正北**（`trueNorthDeg = 0`）。注意 Fragments 转换到 three.js 后坐标轴可能变化（IFC 为 Z 轴向上），实现时以"大门朝南"为准核对一次。

### 9.2 渲染升级

1. **先验证**：确认 `@thatopen/fragments` 3.x 是否能
   - (a) 对模型中的网格替换为自定义的 `MeshStandardMaterial` / `MeshPhysicalMaterial`（包括贴图和透明）；
   - (b) 通过 `onBeforeCompile` 向材质注入自定义着色器代码（第 13.3、13.4 节的开场动画和涟漪需要）；
   - (c) 获取单个构件的几何体或网格（第 13.8 节的选中描边需要）。

   写一个最小试验：把桌面换成带贴图的 HPL 材质，把展示柜玻璃换成透明玻璃，给墙体材质注入一个按距离变透明的着色器片段，截图汇报。
   - 如果都可以：按下面第 2 步在运行时替换材质。
   - 如果不行：改用"展示模型"方案：从 Revit 导出 FBX（带贴图），在 Blender 中整理材质并导出 glTF（`.glb`，Draco 压缩），用作显示层；Fragments 模型保留为隐藏的"交互层"，用于点选和 GlobalId 绑定。两者坐标必须对齐。
2. **材质映射表**（`scene/materials.js`）：按 IFC 材质名称映射为 PBR 材质，贴图使用 CC0 授权的材质库（ambientCG、Poly Haven）。映射示例：
   - `Plank-HPL-white` / `Plank-HPL-black` → 哑光 HPL 板，粗糙度约 0.6
   - `.Vidro`、`TV - Glass` → `MeshPhysicalMaterial`，`transmission` 约 0.9，粗糙度约 0.05
   - `Aluminum`、`Cromado`、`Plank-aluminium-black` → 金属度 1，粗糙度 0.25–0.4
   - `NBS_SafetyFabrications_Steel-Galvanized`、4 m 处金属网板 → 镀锌钢；网板使用带透明通道的格栅贴图（`alphaTest`），做到真正透光
   - `Plaster`、墙体 → 浅暖白乳胶漆，粗糙度 0.9
   - `Concrete, Cast In Situ`、楼板 → 浅灰水磨石或环氧地坪
   - MEP（无材质）：风管 → 镀锌钢；风口和散流器 → 白色喷涂；灯具 → 白色外框 + 可开关的自发光面板（第 13.6 节）
   - 传感器（`ABB - Plastic - White`、`ABB - Glass - Black`、`ABB - Light - LED`）→ 白色塑料、黑色玻璃、LED 自发光
3. **光照**：
   - HDRI 环境光（柔和的白天天空，Poly Haven），通过 `PMREMGenerator` 生成环境贴图，作为基础照明。只加载一张，不随时间更换。
   - 一盏方向光代表太阳，方向、颜色、强弱和阴影软硬按真实时间和太阳辐射变化（第 13.2 节）。软阴影（`PCFSoftShadowMap`），阴影贴图 2048，阴影范围限制在房间及周边。
   - 地面：房间下方放一块只接收阴影的平面（`ShadowMaterial`），让房间像"放在桌面上的模型"，背景透出。
   - 环境光遮蔽：先验证 N8AO 或 three.js 自带的 SSAO / GTAO 后处理在目标设备上的帧率，帧率不达标时改为只在相机静止时开启。
   - 色调映射：从 `ACESFilmicToneMapping` 改为 `AgXToneMapping` 或 `NeutralToneMapping`（three r185 都支持），对比后选择颜色更自然的一个。
   - 背景：画布透明，背景由 CSS 渐变绘制（第 13.2 节）。
4. **按需渲染**：目前 `animate()` 每一帧都在渲染。改为只在相机移动、数据变化或有动画进行时渲染，其余时间停止。这同时能大幅降低玻璃面板模糊的开销。实现一个 `requestRender()` 和"活动动画计数"，所有动效通过它申请渲染。

### 9.3 看清室内（不删除细节）

- **墙体自动淡出**：根据相机方向，朝向相机的一面或两面墙降低不透明度（约 0.12），其余墙保持不透明。镜头转动时平滑过渡（300 ms）。建议用 `alphaHash`（抖动透明），避免透明物体排序问题。
- 6 m 处的吊顶默认隐藏（现有逻辑已隐藏 MEP 模型中的 `IFCCOVERING`），4 m 处的金属网板保留但透光。
- 设备主题中 MEP 可见；首页和环境主题中 MEP 默认可见但不突出（不加任何高亮）。

### 9.4 传感器标记

- 统一为小型玻璃质感圆点（直径约 14 px，屏幕空间大小固定），中间一个状态色点。
- 在环境和能耗主题中，标记上方出现读数标签（薄玻璃胶囊）。
- 新读数到达时标记闪一次（一次性的光环扩散，400 ms）。
- 离线或数据过期：标记变灰，无动画。
- 鼠标靠近时有磁吸效果（第 13.12 节）。
- 选中时：标记放大，并成为传感器详情面板的"起点"（第 10 节的共享元素过渡）。
- 占用传感器（VS341）：不显示标记，只在有占用时在座位上方显示淡淡的人形图标。目前 VS341 没有实时数据，客户模式下不显示占用。
- 现有的标签遮挡检测（`updateSensorOcclusion`）和移动端防重叠（`resolveMobileMarkerCollisions`）保留。

## 13. 细节与标志性效果

### 13.1 性能预算

目标设备：使用集成显卡的笔记本，1440 × 900。

| 效果 | 什么时候消耗 | 开销 | 控制方法 |
| --- | --- | --- | --- |
| 实时光照和背景（13.2） | 每 10 分钟重算一次阴影 | 几乎为零 | 背景用 CSS；阴影贴图只在太阳方向变化时更新一帧 |
| 玻璃模糊 | 场景重新渲染时，玻璃下方要重新模糊 | 中 | 按需渲染；同时可见的玻璃不超过 3 组 |
| 写实材质、阴影、环境光遮蔽 | 每次渲染 | 中到高 | 阴影贴图固定 2048；环境光遮蔽不达标时只在静止时开启 |
| 涟漪和透视镜（13.4） | 只在效果进行中（约 2 s） | 中 | 数字层几何体在加载时预先生成；用 `alphaHash` |
| 选中描边（13.8） | 有选中对象且场景渲染时 | 中（多一次渲染） | 没有选中对象时关闭该后处理 |
| 夜间灯光（13.6） | 每次渲染 | 低 | 用地面光斑贴片代替真实光源 |
| 开场动画（13.3） | 只在加载后约 3 s | 中 | 第二次访问缩短为 0.6 s |
| 一天回放（13.5） | 播放期间连续渲染 | 中到高 | 阴影最多每 200 ms 更新一次；目标 ≥ 45 fps |
| 待机展示（13.7） | 待机期间连续渲染 | 中 | 限制为 30 fps；页面不可见时暂停 |
| 能耗流线（5.3） | 显示期间连续渲染 | 低到中 | 只在能耗主题显示 |
| 玻璃跟随反光、按钮回弹（13.12） | 鼠标移动时 | 极低（纯 CSS） | 用 `requestAnimationFrame` 节流 |
| 屏幕分辨率（尤其是 4K 大屏） | 每次渲染 | 4K 的像素数是 1080p 的 4 倍 | 限制三维渲染分辨率；画质自适应（13.13） |

说明：模型本身很轻（三个模型共约 120 个构件、约 13 万个三角形，三个 .frag 文件合计约 350 KB），对任何近几年的显卡都不是负担。卡顿风险主要来自**像素数量**（高分辨率屏幕）和**逐像素的后处理**（玻璃模糊、环境光遮蔽、描边），所以控制手段集中在这两方面。

验收（同时写入第 17 节）：首页和环境、设备主题静止时不连续渲染；转动视角和打开面板时 ≥ 50 fps；涟漪期间 ≥ 50 fps；回放 ≥ 45 fps；待机稳定 30 fps。内部模式显示实时帧率，方便检查。

### 13.2 实时光照（轻量版"真实天空"）

**目标**：房间周围的光线随真实时间和天气变化，早上偏暖，中午明亮，阴天柔和，傍晚偏橙。**不画云，不做天空盒，不做大气散射模型，不更换 HDRI。** 所有效果只靠改变几个参数实现，几乎没有额外渲染开销。

**输入**

1. **太阳位置**：用 `suncalc`（npm，体积很小）按香港理工大学坐标（约 22.304°N，114.180°E）和当前时间计算太阳方位角和高度角。每 10 分钟更新一次（与太阳辐射数据同步）；回放时按回放时间计算。
2. **晴朗程度**：晴空指数 k = 实测太阳辐射 ÷ 晴空理论辐射。
   - 晴空理论辐射用 Haurwitz 模型：G_clear = 1098 · cosθz · exp(−0.057 / cosθz)（W/m²，θz 为太阳天顶角）。
   - k ≥ 0.7 视为晴，0.3–0.7 多云，< 0.3 阴。
   - 太阳高度角低于 5° 时不计算 k（数值不稳定），只按时间处理。
   - 太阳辐射数据缺失（超过 30 分钟）时按晴天处理，只随时间变化，并且不在界面上声称天气状况。
3. **房间朝向**：大门朝南，IFC 的 +Y 方向为正北（第 9.1 节）。写在配置参数 `trueNorthDeg = 0` 中，以便以后模型调整时修改。

**输出**

1. **背景**：WebGL 画布设为透明（`alpha: true`），背景由画布后面容器的 CSS 渐变绘制，零 WebGL 开销。
   - 准备 6 组关键色：夜、黎明、上午、正午、下午、黄昏。每组是上下两个颜色（天顶色、地平色），按太阳高度角在相邻两组之间插值。
   - 多云和阴天时，把颜色向中性灰拉近，降低饱和度，缩小上下色差。
   - 通过 CSS 变量更新，`transition` 2 s。
   - 颜色整体保持很浅（浅色模式），保证玻璃面板上文字的对比度。
2. **方向光（太阳）**：
   - 方向 = 太阳方向（考虑 `trueNorthDeg`）。
   - 颜色按高度角插值：低角度暖（约 3000 K），高角度中性（约 5500 K）。
   - 强度随 k 变化：晴天强，阴天弱。
3. **阴影**：晴天清晰浓重；多云变软变淡；阴天几乎没有（只保留环境光遮蔽）。通过 `shadow.radius` 和地面 `ShadowMaterial` 的不透明度随 k 变化实现。设置 `renderer.shadowMap.autoUpdate = false`，只在光照方向变化时设 `needsUpdate = true` 重算一帧。
4. **环境光**：HDRI 的强度和整体色调随时段微调（早晚略暖略暗，正午略亮），不更换贴图。
5. **太阳落山后**：
   - 浅色模式：背景保持较亮的"蓝调时刻"颜色（保证浅色界面可读），房间内灯具亮起（第 13.6 节的灯光，但背景不变暗）。
   - 深色模式：完整的夜间效果（第 13.6 节）。

**讲述方式**：ZB202 没有窗户，所以这里的光线代表"外面的世界"。外面的天气和时间一直在变，房间里的温湿度和 CO₂ 一直被控制得很稳定，这正是空调系统和 AI 推荐在做的事。身份区的"室外 31° · 晴"一行与背景光照保持一致。

### 13.3 开场动画：从图纸到孪生

**目标**：页面加载时，用两到三秒讲完"BIM → 数字孪生"的过程。加载进度和动画进度是同一件事，不另做加载转圈。

1. **加载中**：地面上逐步画出平面图线条（墙体轴线和轮廓、柱、门的开启线、轴网和尺寸标注）。**线条绘制进度 = 真实的模型加载进度**，不是固定时长的假进度。平面图线条数据由离线脚本从 IFC 生成（新增 `npm run bim:plan`，用 web-ifc 读取墙体、柱、门，输出 `web/public/models/plan-lines.json`）。
2. **加载完成**：一个水平剖切面从地面升到吊顶高度（约 900 ms），构件随剖切面"长"出来。用 three.js 的裁剪平面实现，对 Fragments 模型也适用。此时构件显示为数字层样式（第 13.4 节的线框和半透明材质）。
3. **材质显现**：复用第 13.4 节的数字层系统，从整个房间都是数字层开始，让"写实区域"从房间中心向外扩散，直到整个房间变为写实材质（约 800 ms）。
4. **传感器亮起**：传感器标记依次亮起（间隔 60 ms），同时界面元素（胶囊、标签栏、AI 卡）从边缘淡入滑入。
5. **镜头**：全程从较远处缓慢推近到首页机位。
6. 平面图线条在开场后淡出。

规则：

- 首次访问完整播放（加载完成后约 3 s）；同一浏览器再次访问缩短为 0.6 s（只有剖切面上升和界面淡入）。用 `localStorage` 记录，读写放在 try/catch 中，失败时按首次访问处理。
- 点击或按任意键可以跳过。
- 减少动态效果时：直接淡入。
- 加载失败：平面图线条停在当前进度并变灰，显示错误信息和"重新加载"按钮（原有功能）。

### 13.4 涟漪露出数字层

**目标**：点击场景空白处时，从点击位置泛起涟漪，涟漪经过的区域短暂露出房间的"数字层"，表达"真实房间背后有一个完整的数字模型"。

**数字层的内容**（加载完成后一次性生成）：

- 建筑构件的轮廓线（`EdgesGeometry`，角度阈值约 30°），强调色细线。
- MEP（风管、风口、水管、灯具）以半透明强调色材质显示，即使在吊顶和网板后面也能看到。
- 传感器的设备编号标签（如"AM103-05"）。
- 传感器之间的数据连线：如果 LoRaWAN 网关的位置已知，从各传感器连到网关；未知时，只从每个传感器向上画一条细光线到吊顶高度的"数据平面"，**不画不存在的网络拓扑**（见第 18 节）。

**交互**：

- **点击**（按下到松开 < 250 ms，移动 < 5 px）场景空白处（不是标记、不是界面元素）：
  - 涟漪半径在 900 ms 内从 0 扩展到约 6 m（ease-out），涟漪前沿是一圈强调色光环（宽约 0.25 m），贴着地面和墙面扩散。
  - 涟漪经过的区域：墙体和网板变为抖动透明，数字层显现。
  - 保持 600 ms 后，数字层在 500 ms 内淡出，恢复写实。
- **按住**（按住不动超过 400 ms）：变为"透视镜"。鼠标下方表面周围半径约 1.2 m 的圆形区域显示数字层，跟随鼠标移动；按住期间禁止旋转视角；松开后 300 ms 淡出。
- **拖动**（移动超过 5 px）：正常旋转视角，不触发涟漪。
- 触屏：轻点触发涟漪，长按触发透视镜。
- 点击传感器标记时不触发数字层，只有一圈小光环，然后选中并飞过去。

**实现**：

- 所有相关材质共享一组 uniform：涟漪中心（世界坐标）、半径、前沿宽度、整体淡出系数；透视镜使用同一组 uniform（固定半径、中心跟随鼠标射线与表面的交点）。
- 数字层材质：只在"距中心 < 半径"的区域显示，前沿处更亮。
- 写实材质（墙体、网板、吊顶）：通过 `onBeforeCompile` 注入，在涟漪区域内用 `alphaHash` 变透明。依赖第 9.2 节第 1 步的验证结果；如果 Fragments 不支持，则作用在 glTF 展示层上。
- 只在效果进行中申请渲染（按需渲染）。

### 13.5 一天回放

**目标**：几秒钟内展示一整天的真实数据，是体现"数据丰富"最诚实的方式。

- **入口**：环境主题 CO₂ 时间轴左侧的"回放"按钮。
- **范围**：过去 24 小时（以后可以扩展为选择日期）。
- **数据**：桥接新增一条消息 `room-history-request`（参数：小时数、时间步长，默认 24 小时、10 分钟），一次性返回 5 个环境传感器的 CO₂ / 温度 / 湿度、插座有功功率、太阳辐射、期间发生的告警事件。返回结果缓存，再次回放不重新请求。现有的 `sensor-history-request` 不变。
- **播放**：默认 24 秒播完一天（每秒 1 小时），速度可选 0.5× / 1× / 2×；可以拖动时间轴到任意时刻。
- **回放中同步变化的内容**：状态胶囊的数值、传感器光晕颜色、标记读数、能耗流线（在能耗主题时）、背景光照和太阳方向（按回放时刻和当时的太阳辐射）、告警事件在对应时刻闪现。
- **数值显示**：数字按每个采样点跳变（显示真实采样值）；光晕颜色在采样点之间用 300 ms 过渡，避免闪烁。
- **数据缺口**：缺失的时段显示为缺口，标记变灰，不插值填补。
- **标记**：回放期间顶部居中显示靛蓝色"回放 · 10月14日 09:30"标记，时间随播放变化。AI 卡在回放期间隐藏（以后有推荐历史时可显示当时的推荐）。
- **退出**：点击"回到实时"或按 Esc，平滑过渡回当前实时数据。回放期间实时数据继续在后台接收。
- **性能**：播放期间连续渲染；阴影最多每 200 ms 更新一次；目标 ≥ 45 fps。

### 13.6 深色模式即夜晚

- **深色模式 = 夜间光照**：
  - 背景：深靛蓝到近黑的 CSS 渐变（与第 13.2 节"夜"的关键色一致，但更暗）。
  - 太阳方向光关闭；HDRI 强度降到很低，色调偏冷。
  - 6 个灯具（lab-mep 中的 `Plain Recessed Lighting Fixture 300x1200`）的面板变为暖白自发光（约 4000 K）。
  - 每个灯具下方的地面和桌面上放一块"光斑"贴片：径向渐变贴图、叠加混合、不写深度。这样不用 6 盏真实光源也能表现灯光照亮地面的效果，开销很低。如果帧率有余量，可以试验 `RectAreaLight` 作为增强，先测帧率。
  - 房间内整体环境亮度适当提高，形成"夜里亮着灯的实验室"的效果；房间外是暗的。
  - 夜间不渲染太阳阴影。
- **切换**：深浅模式切换时，光照参数在 1200 ms 内交叉过渡；切换到深色时，灯具按顺序依次亮起（间隔 80 ms，每个 300 ms 渐亮），不做闪烁效果；切换到浅色时依次熄灭。
- **浅色模式的夜间**：见第 13.2 节第 5 点（灯具亮起，背景保持较亮）。
- 灯具即使在 MEP 图层关闭时也保持可见（只有灯具，不含风管）。

### 13.7 大屏待机展示

- **开启**：设置中的"待机展示"开关，或 URL 参数 `?kiosk=1`（用于实验室大屏）。默认关闭。
- **触发**：无任何操作超过 3 分钟（可配置）。
- **内容**：
  - 依次展示总览 → 环境 → 能耗 → 设备，每个约 20 秒，主题面板正常打开。
  - 镜头围绕当前主题机位的目标点缓慢摆动（左右各约 25°，约 120 秒一个来回），不做 360° 环绕，以免转到墙背面。
  - 每轮展示中触发一次涟漪露出数字层（第 13.4 节），展示这个效果。
  - 显示的仍是实时数据；演示模式开启时，"演示数据"标记照常显示。
- **提示**：底部显示一个小的薄玻璃标记"待机展示中 · 触碰屏幕即可操作"。
- **退出**：任何鼠标、键盘、触摸操作立即停止（当前帧），回到首页机位。
- **性能**：待机期间限制为 30 fps；页面不可见时暂停。

### 13.8 选中效果：柔和描边

- 选中传感器或构件时，加一圈强调色的柔和发光轮廓（约 2 px，带外发光衰减），**不改变构件颜色**，保留写实材质。出现时 200 ms 淡入，然后轻柔脉动一次。
- 设备主题中，鼠标悬停在可选构件上时显示更淡的描边（1 px，40% 不透明度）。
- 替换现有代码中通过 `fragmentsModel.highlight` 改变构件颜色的做法（`styleBoundObject`、`selectIfcItem` 等）。
- 实现：three.js `OutlinePass` 或 pmndrs `postprocessing` 的 `OutlineEffect`，**只在有选中对象时开启**。需要获取单个构件的网格（第 9.2 节第 1 步的验证 (c)）；如果 Fragments 不直接提供，在选中时用该构件的几何体临时创建一个覆盖网格用于描边。

### 13.9 术语说明

- 专业术语和单位带细虚线下划线。桌面端悬停、触屏轻点时，从该词处长出一个小的厚玻璃说明框，一到两句话。
- 文案放在 `i18n.js` 的 `glossary` 中，三种语言。初稿（简体中文，供 Claude Code 补全另外两种语言，最终由用户确认）：

| 术语 | 说明初稿 |
| --- | --- |
| CO₂ / ppm | 空气中二氧化碳的浓度，ppm 表示"百万分之一"。人呼吸会产生 CO₂，浓度越高，说明通风越不足。 |
| 800 ppm | 香港室内空气质素认证计划中"卓越级"的 CO₂ 标准（8 小时平均低于 800 ppm）。 |
| 1000 ppm | 同一计划中"良好级"的 CO₂ 标准。 |
| 相对湿度 | 空气中水汽含量占当前温度下最大含量的百分比。 |
| PM2.5 | 直径 2.5 微米以下的细颗粒物，能深入肺部。 |
| dB(A) | 按人耳感受加权的声音强度单位。 |
| 新风量 L/s | 每秒送入房间的室外新鲜空气量，单位为升每秒。 |
| 新风阀开度 | 控制新风进入量的风阀打开的百分比。 |
| 有功功率 kW / 用电量 kWh | 功率是当前用电的快慢；用电量是一段时间内累计用掉的电。 |
| 估计人数 | 没有直接计数时，根据 CO₂ 变化等数据推算出的人数。 |
| 太阳辐射 W/m² | 每平方米地面接收到的太阳能量，用来判断晴天还是阴天。 |
| 数字孪生 | 与真实房间同步的数字模型，包含建筑构件、设备和实时数据。 |

### 13.10 截图导出

- **入口**：右上工具按钮组中的相机图标。
- **输出**：当前视角的 PNG 图片，分辨率为屏幕的 2 倍。
  - 场景部分：在截图时单独渲染一帧并立即读取画布（同一任务中调用 `renderer.render` 后 `canvas.toBlob`），不需要常开 `preserveDrawingBuffer`。
  - 叠加信息：用 Canvas 2D 绘制一个简洁的信息层，包括房间名、日期时间（香港时间）、4 个状态值及状态、当前主题名称、底部一行"ZB202 Digital Twin"。**不使用 html2canvas**（它不支持 `backdrop-filter`，玻璃效果会截坏）。
  - 演示模式下加"演示数据"水印；回放时加"回放 · 时间"标注。
  - 文件名：`ZB202_2026-10-15_1130.png`。
- **反馈**：场景上一次 120 ms 的白色闪光，缩略图飞向相机按钮，然后提示"已保存"。

### 13.11 空状态与加载状态

- **加载中**：模型加载见第 13.3 节。数据面板在第一批数据到达前显示骨架占位块（带轻微的闪光动画，对应真实的加载过程）；超过 10 秒仍无数据，切换为对应的空状态。
- **空状态**（三种语言，配 Phosphor 线性图标，不用插画素材）：

| 情况 | 显示 |
| --- | --- |
| 没有告警 | "一切正常"，配一个对勾图标 |
| 数据服务断开 | "暂时无法连接数据服务，正在重试…"，显示真实的重连倒计时 |
| 所选时间段没有记录 | "这个时间段没有记录" |
| 搜索无结果 | "没有找到"xxx"" |
| AI 推荐数据中断 | "推荐更新中断 · 最后更新 xx:xx"，保留最后一次推荐并变灰 |
| 插座控制不可用 | "插座控制暂时不可用"，一句话原因 |

- 任何情况下都不显示单独的"—"。

### 13.12 指针与点击细节

- **保留系统鼠标**，不做自定义跟随光标。按情况切换系统样式：可点击处为手形；在场景中拖动旋转时为抓取 / 抓取中；内部模式坐标拾取时为十字。
- **玻璃反光跟随鼠标**：所有玻璃元素加一个伪元素，绘制一块柔和的白色径向渐变（半径约 120 px，不透明度约 0.18），位置由 CSS 变量 `--px`、`--py` 控制，在 `pointermove` 中用 `requestAnimationFrame` 节流更新。鼠标进入时淡入，离开时淡出。触屏设备（`(hover: none)`）和"降低透明度"时关闭。
- **按钮按下**：缩小到 97%，玻璃高光变亮；松开时轻微回弹（见第 12 节）。
- **标签栏滑块**：按住标签栏时，滑块轻微放大并变得更通透，可以拖动到其他标签，松开后吸附到最近的一项（参考 Liquid Glass 控件在交互时变成玻璃的效果）。
- **标记磁吸**：鼠标距离某个可见标记小于 28 px（屏幕距离）时，最近的那个标记进入悬停状态：放大 1.3 倍，并预览读数；此时点击即选中该标记，不需要精确点中。触屏的磁吸半径为 44 px。
- **场景中的点击、拖动、按住**：规则见第 13.4 节，所有场景指针交互统一在 `ui/pointer.js` 中判断，避免与旋转视角冲突。

### 13.13 画质自适应

不同电脑和屏幕的性能差别很大，不能只按一台电脑调好。设三档画质，自动选择，也可以在内部模式中手动指定：

| 档位 | 三维渲染分辨率 | 阴影 | 环境光遮蔽 | 描边 | 玻璃模糊 |
| --- | --- | --- | --- | --- | --- |
| 高 | 设备像素比，最高 2 | 2048，软阴影 | 开启 | 开启 | 标准 |
| 中 | 设备像素比，最高 1.5 | 2048 | 只在相机静止时 | 开启 | 标准 |
| 低 | 固定 1（4K 屏上再乘 0.75） | 1024 | 关闭 | 改为简单轮廓线 | 模糊半径减半 |

- **自动选择**：开场动画结束后的前几秒测量实际帧率，低于目标时降一档；运行中连续一段时间低于目标再降一档，不自动升档（避免来回跳）。用户在同一浏览器中的档位记录在 `localStorage`。
- **限制渲染分辨率**：三维画面按上表的分辨率渲染后拉伸显示，界面文字仍按屏幕原生分辨率显示，所以文字始终清晰。在大屏上，观看距离较远，三维画面降低分辨率几乎看不出差别。
- **大屏**：`?kiosk=1` 时默认从"中"档开始。
- 内部模式显示当前档位和帧率。

## 19. 部署到云服务器的注意事项

**先澄清一个常见误解**：把程序放到云服务器上，**不会让三维画面更流畅**。三维渲染、玻璃模糊、动画全部发生在观看者自己的浏览器里，用的是观看者电脑的显卡。服务器只负责两件事：把网页和模型文件发给浏览器，以及通过 WebSocket 推送数据。画面是否流畅取决于观看者的电脑和屏幕（第 13.13 节），与服务器无关。

（唯一让服务器承担渲染的方式是"像素流"，即服务器用显卡渲染后把视频流传给浏览器，Porsche 配置器就是这样做的。这需要带显卡的云服务器，成本高，延迟也更大，本项目不需要。）

云服务器带来的真正好处：不依赖实验室某台电脑开机，任何地方都能打开；数据桥接和 AI 策略引擎可以 24 小时运行。

部署时需要处理的问题：

1. **首次加载的文件大小**：模型文件很小（约 350 KB），但写实渲染会加入贴图和 HDRI。要求：
   - 贴图压缩为 KTX2（Basis），HDRI 使用 1K 或 2K 分辨率；
   - 首屏需要下载的全部文件（不含按需加载的字体分片）控制在约 10 MB 以内；
   - 静态文件开启 gzip / brotli 压缩和长期缓存，第二次打开几乎不需要重新下载。
2. **HTTPS 和 WSS**：现有前端用 `ws://<主机名>:8787` 连接桥接。在云上，网页必须走 HTTPS，WebSocket 必须走 `wss://`，并通过反向代理（如 Nginx 或 Caddy）放在同一个域名下（例如 `wss://<域名>/bridge`），不再直接暴露 8787 端口。前端的连接地址改为可配置。
3. **安全（最重要）**：
   - 现在页面可以通过 MQTT 真实开关实验室的插座。放到公网后，**如果没有登录，任何拿到链接的人都能开关插座**。部署到公网前必须加登录：至少区分"只读查看"（客户、访客）和"可以控制"（实验室成员），插座控制和以后的 AI 自动控制只对后者开放，并在服务器端校验，不能只在前端隐藏按钮。
   - InfluxDB 令牌、MQTT 密码只保存在服务器的环境变量中，绝不能出现在前端代码里。
   - 演示模式、内部模式的 URL 参数只影响显示；任何会改变设备状态的操作都要经过服务器端的权限检查。
4. **服务器所在地区**：如果服务器在内地而观看者在香港（或反之），跨境网络可能不稳定，这也是字体必须自托管、不依赖 Google Fonts 的原因之一。
5. **数据延迟**：传感器每 10 分钟上报一次，服务器带来的几十到几百毫秒网络延迟对显示没有影响；插座控制的反馈会稍慢一点，第 5.3 节的"已排队 → 已发送 → 已生效"状态显示正好覆盖这个情况。
