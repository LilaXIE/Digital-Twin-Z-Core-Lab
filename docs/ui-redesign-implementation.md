## 2. 方案 9.2 第 1 步的验证结果

| 项目 | 结果 |
| --- | --- |
| (a) 替换为自定义 PBR 材质 | Fragments 3.x 内部用 `MeshLambertMaterial`，不能原地换。但 `getItemsGeometry()` 能取出每个构件的每段几何体，`editor.getElements()` 能取出每段对应的 IFC 颜色。用这两项在运行时**自建显示层**，可以使用任意材质 |
| (b) `onBeforeCompile` 注入着色器 | 自建网格可以注入，涟漪、透视镜、墙体淡出、开场剖切都用这一套 |
| (c) 获取单个构件的几何体 | 可以，每个构件按材质合并为独立网格，用于选中描边、拾取和数字层 |

结论：不需要走"Revit → FBX → Blender → glTF"的展示模型方案。显示层直接由 Fragments 几何重建，坐标天然一致，Revit 的全部族都保留（126 个构件、约 12.5 万三角形），Fragments 模型继续作为 IFC 属性的数据来源。几何片段按"构件 × 材质"合并后，每帧绘制调用从约 3,200 次降到约 190 次。

朝向核对：大门在 three.js 坐标的 +Z 一侧，所以正南 = +Z、正北 = −Z，与"IFC +Y 为正北"一致（`config/site.js` 中 `trueNorthDeg = 0`）。

## 3. 与方案不同的地方

| 方案 | 实际 | 原因 |
| --- | --- | --- |
| 中文用鸿蒙字体（8.2.1） | **思源黑体（Noto Sans SC / HK）+ Inter**，全部自托管 | 已按方案要求阅读鸿蒙字体许可全文：第 2.2 条禁止对字体作任何修改，而网页必需的分片和 woff2 转换都属于修改；不分片的 TTF 每个字重约 8 MB，远超首屏预算。按方案的备选改用思源黑体（SIL OFL，允许分片）。繁体字体文件只在选择"繁"时才加载 |
| HDRI 来自 Poly Haven、贴图来自 ambientCG（9.2） | three.js 自带的程序化环境光（`RoomEnvironment`）+ 程序生成的贴图（水磨石、HPL 细纹、镀锌钢、网板格栅） | 开发环境无法访问这两个网站。改用的方案零下载、没有授权需要跟踪，也不需要 KTX2 压缩。以后如需真实 HDRI，只改 `scene/lighting.js` 一处 |
| 选中描边用 `OutlinePass`（13.8） | 反向外壳（沿平滑法线外扩的背面壳），低档改为线框 | 不需要额外的后处理渲染，透明画布下也没有边缘问题；只在有选中对象时存在 |
| 墙体淡出用 `alphaHash` 抖动（9.3） | 墙体用真实半透明；涟漪和透视镜仍用抖动 | 1× 分辨率屏幕上抖动的颗粒很明显；墙是单层，透明排序不成问题。门随所在的墙一起淡出 |
| 6 m 吊顶默认隐藏（9.3） | 无需处理 | 三个模型中都没有 6 m 吊顶（MEP 模型里隐藏 `IFCCOVERING` 原本就是空操作）；4 m 网板在建筑模型中，保留并透光 |
| 环境传感器光晕在"地面上"（5.2） | 桌上的传感器光晕落在桌面，墙上的传感器光晕落在墙前的地面 | 三个环境传感器放在会议桌上，地面光晕会被桌面挡住一半 |
| 色调映射在 AgX / Neutral 中选择 | `NeutralToneMapping` | 颜色更接近 Revit 材质原色；AgX 整体偏暗、偏灰 |
| 必要时引入轻量动画库 | 未引入 | CSS、Web Animations 和 View Transitions 已够用 |
| AI 详情页的"AI 自动 / 手动"切换 | 只读并说明原因；演示模式下可切换 | 目前没有 AHU 数据，也没有 FMO 授权 |

另外新增了两项方便检查的功能：

- URL 参数 `?quality=high|medium|low` 用于固定画质档位。
- 内部模式下 `&kioskIdle=秒数` 用于缩短待机展示的等待时间。

## 4. 验证情况

- 单元测试：`npm run test:ui`（新增，7 项）和 `npm run test:strategy`（31 项）全部通过；`npm run build` 通过。
- 界面检查：配合模拟数据桥接（`npm run bridge:mock`）和演示模式，在 1024 / 1280 / 1440 / 1920 宽度下截图检查了以下内容：
  - 首页、三个主题、传感器详情、AI 详情页、告警弹层、设置菜单、胶囊悬停曲线；
  - 深色夜间灯光、开场平面图绘制、数字层涟漪、一天回放、演示模式、待机展示、截图导出；
  - 简体、繁体、英文三种语言。
- 按需渲染：静止时渲染循环停止（内部模式状态栏显示 idle），只有镜头飞行、淡出、光晕、流线、回放等进行时才连续渲染。
- **未能实测的部分**：开发容器只有软件渲染（约 1 帧/秒），因此帧率、画质自适应和动效流畅度都没有测到真实数字，第 17 节的帧率指标需要在实验室大屏和一台只有集成显卡的笔记本上实测。内部模式（`?mode=internal`）左下角会显示帧率、画质档位和绘制调用数，方便现场检查。
- `npm run test:bridge` 需要连接真实的 InfluxDB，开发容器中无法运行。新增的 `room-history-request` 已有单元测试覆盖查询与解析，但仍需在本地接真实数据跑一次。

## 6. 需要确认或之后处理

1. 4.5 节的温湿度和 PM2.5 阈值仍是暂定值，确认后修改 `web/src/twin/config/thresholds.json`。
2. 术语说明的繁体和英文译文是我补充的，请审阅（`web/src/twin/i18n.js` 中的 `GLOSSARY`）。
3. WS523-01、05、06 在模型中还没有位置，目前只显示在能耗面板中，不画流线。在 Revit 中补放后重新转换即可，代码不用改。
4. LoRaWAN 网关位置确认后，可在 `scene/digital-layer.js` 中把竖直数据线改成连向网关。
5. 部署到公网前必须按第 19 节加登录和服务器端权限校验。前端的桥接地址已经可以通过 `VITE_ZB202_BRIDGE_URL` 或 `?bridge=` 配置。
